# Test App

Демонстрационное приложение на Ruby on Rails 8 для обработки заказов с изменением
баланса пользовательского счёта.

Реализовано:

- пользователи
- счета пользователей
- заказы со статусами
- журнал финансовых операций
- завершение заказа
- отмена успешного заказа с обратной финансовой операцией

## Стек

- Ruby 4
- Ruby on Rails 8
- PostgreSQL
- RSpec
- money-rails

## Запуск проекта

Установить зависимости:

```bash
bundle install
```

Создать и подготовить базу данных:

```bash
rails db:setup
```

Запустить приложение:

```bash
rails server
```

Запуск тестов:

```bash
bundle exec rspec
```

# Архитектура

## Денежные значения

Для работы с деньгами используется gem `money-rails`.

В базе данные хранятся в минимальных единицах валюты (cents):

```text
$10.50 = 1050
```

В приложении используются объекты `Money`.

В проекте используется одна валюта по умолчанию — USD.

## Упрощённый Ledger-подход

Текущая реализация использует упрощённый журнал финансовых операций.

Изменения денежных средств фиксируются в таблице `account_transactions`.

В дальнейшем эту модель можно расширить до полноценной double-entry
bookkeeping системы.

`AccountTransaction` является источником финансовой истории.

Баланс счёта (`accounts.balance_cents`) является денормализованным текущим
состоянием и используется для быстрого доступа.

Изменение баланса выполняется только вместе с созданием финансовой операции
внутри одной транзакции БД.

Исходные финансовые операции не изменяются и не удаляются.

## Согласованность данных

Изменение статуса заказа, создание финансовой операции и изменение баланса
выполняются внутри одной транзакции БД.

Это гарантирует, что невозможно получить промежуточное состояние:

- заказ успешный, но баланс не изменился;
- баланс изменился, но финансовая операция не создана;
- операция создана, но статус заказа не изменился.

## Защита от конкурентных операций

Для финансовых операций используется блокировка строк базы данных (`SELECT FOR UPDATE`).

Во время завершения или отмены заказа блокируются:

- заказ;
- счёт пользователя.

Это предотвращает race condition при одновременных запросах.

Например:

```text
POST /orders/1/complete
POST /orders/1/complete
```

Даже если два запроса выполняются одновременно, финансовая операция будет
создана только один раз.

## Идемпотентность

Финансовые операции защищены от повторного выполнения.

В базе данных используется уникальный индекс:

```text
(order_id, transaction_type)
```

Это гарантирует, что один заказ не сможет создать несколько одинаковых операций.

# Основные принципы реализации

- бизнес-операции вынесены в service objects;
- финансовая история хранится отдельно от текущего состояния баланса;
- изменения денег выполняются атомарно;
- повторное выполнение операций безопасно;
- конкурентные запросы не приводят к двойному изменению баланса.

## Двойная бухгалтерская запись

Текущая реализация использует упрощённый ledger-подход: финансовая операция
напрямую связана с изменением одного счёта пользователя.

При двойной бухгалтерской записи каждая финансовая операция должна создавать
как минимум две проводки debit и credit.

Сумма всех debit и credit внутри одной операции должна быть равна:

```text
debit = credit
```

Пример операции оплаты заказа:

```text
Order payment $50

Platform account
debit  $50

User account
credit $50
```

Такой подход позволяет:

- полностью восстановить баланс из истории операций;
- гарантировать, что деньги не появляются и не исчезают без соответствующей операции;
- проводить полный аудит движения денежных средств;
- выполнять сверку операций.

Баланс счёта может оставаться денормализованным полем для быстрого доступа, но
его изменение должно происходить только вместе с созданием ledger-записей
внутри одной database transaction.

# API

## Создать заказ

```shell
curl \
  -X POST \
  http://localhost:3000/orders \
  -H "Content-Type: application/json" \
  -d '
  {
    "order": {
      "amount_cents": 1000
    }
  }'
```

Пример результата:

```json
{
  "id": 1,
  "status": "created",
  "amount": {
    "value": "10.00",
    "currency": "USD"
  },
  "transactions": []
}
```

## Получить список заказов

```shell
curl http://localhost:3000/orders
```

Пример ответа:

```json
[
  {
    "id": 1,
    "status": "created",
    "amount": {
      "value": "10.00",
      "currency": "USD"
    }
  }
]
```

## Получить заказ

```shell
curl http://localhost:3000/orders/1
```

Пример ответа:

```json
{
  "id": 1,
  "status": "created",
  "amount": {
    "value": "10.00",
    "currency": "USD"
  },
  "transactions": []
}
```

## Получить счёт пользователя

```shell
curl http://localhost:3000/users/1/account
```

Пример ответа:

```json
{
  "id": 1,
  "user_id": 1,
  "balance": {
    "value": "50.00",
    "currency": "USD"
  }
}
```

## Завершить заказ

```shell
curl \
  -X POST \
  http://localhost:3000/orders/1/complete
```

Пример результата:

```json
{
  "id":1,
  "status":"completed",
  "amount":{
    "value":"10.00",
    "currency":"USD"
  },
  "user_id":1,
  "transactions":[
    {
      "id":1,
      "type":"debit",
      "amount":{
        "value":"-10.00",
        "currency":"USD"
        }
    }
  ]
}
```

## Отменить заказ

Запрос:

```shell
curl \
  -X POST \
  http://localhost:3000/orders/1/cancel
```

Пример результата:

```json
{
  "id": 1,
  "status": "cancelled",
  "amount": { "value": "10.00", "currency": "USD" },
  "user_id": 1,
  "transactions": [
    {
      "id": 1,
      "type": "debit",
      "amount": { "value": "-10.00", "currency": "USD" }
    },
    {
      "id": 2,
      "type": "credit",
      "amount": { "value": "10.00", "currency": "USD" }
    }
  ]
}
```
